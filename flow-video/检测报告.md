## 结论

整体安全设计比较用心，没有发现严重漏洞。发布说明里的几项关键修复在代码里都能找到对应实现。有几处值得注意的低到中等风险，见下文。

## 核对通过的部分

| 项目 | 结果 |

## 发现的问题

### 1. 【中】本地 Bridge 的令牌形同虚设，任何已安装的 Chrome 扩展都能控制软件

`app/services/local_bridge.py:247` 把 `/heartbeat` 设为免令牌，而 `POST /heartbeat` 的返回值里直接带着令牌（第 437 行）。`bridge_security.py` 又允许任意 `chrome-extension://` 来源访问。

后果：电脑上任何一个 Chrome 扩展（包括恶意扩展）都能先调 `/heartbeat` 拿到令牌，然后读取任务、提示词，下载已登记的媒体文件，或者提交伪造的事件，改写本地数据库。本机其他程序也一样（请求不带 Origin 头就能通过）。

README 承认“仍信任同一用户的本地程序和已安装扩展”，所以这是作者已知、有意接受的边界，但令牌本身起不到保护作用。

建议：在插件 `manifest.json` 里加固定的 `key`，让扩展 ID 固定下来，Bridge 只放行这一个 ID；或者改成首次配对时由用户在软件里手动确认。

### 2. 【低】更新安装脚本用 `assert` 做哈希校验

`scripts/install_update.py` 里打开安装包前的 SHA-256 校验写成了 `assert`。如果 Python 以 `-O` 运行，或者环境变量里设置了 `PYTHONOPTIMIZE`，这一步会被直接跳过。目前软件不以 `-O` 启动，所以实际风险低（前面的 `updater.verify` 也已经校验过一次），但应改成显式的 `if ... : raise`。

### 3. 【低】表格链接不是 Google 表格时，会原样请求任意地址

`app/services/task_intake.py` 的 `sheet_export_url()` 识别不出 Google 表格链接时直接返回原始地址，再交给 `urllib.request.urlopen`。这个地址可以是内网地址，也可以是 `file://` 本地文件。地址由用户自己填写，所以风险低，但建议只允许 `docs.google.com`。

### 4. 【低】可选组件的依赖没有完全锁定

- `requirements-asr.txt`（本地语音识别）只锁定了顶层包版本，间接依赖没有锁定，也没有哈希校验。
- 自动安装 Node 时用的是 `latest-v22.x`，版本不固定（会校验官方 SHA-256）。

这是供应链风险，只影响用户主动安装的可选组件。

### 5. 【提示】文档和版本信息不一致

- 源码里仍保留 `extension/FlowStudio_Web_Plugin_v1.8.3_IDENTITY_ALIAS_DOWNLOAD`，发布说明却要求“不要加载 1.8.3”。源码用户容易加载错插件。安装包已正确排除它。
- README 开头写的“视频包装新增功能”标注为“当前源码，尚未发布安装包”，和 1.0.0 正式版的说法容易混淆。
- `task_intake.py` 的 User-Agent 仍写着 `FlowStudio/0.13.3`。

### 6. 【提示】安装包没有代码签名

作者已说明：Windows 没有 Authenticode 签名，Mac 没有 Apple 公证。更新校验依赖 GitHub 返回的 SHA-256，如果 GitHub 仓库或账号被盗，校验挡不住篡改过的安装包。
